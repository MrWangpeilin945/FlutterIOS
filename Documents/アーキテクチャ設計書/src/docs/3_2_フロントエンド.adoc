== ディレクトリ構造

[source]
.
└── ResultCollector/ <.>
    ├── app/
    │   ├── api <.>
    │   ├── components <.>
    │   ├── domain <.>
    │   ├── routes <.>
    │   └── utils <.>
    └── public <.>

<.> 設定ファイル(*.config)や環境変数(.env)はrootフォルダ直下に配置

<.> API呼び出しはTanStack Queryを使用 +
apiフォルダ内の資産はOpenAPI設計書から出力したもののみ格納する(手編集NG)

<.> コンポーネントはcomponentsフォルダ直下に格納する +
小分けが必要になればサブディレクトリを作成する

<.> 定数や共通のモデルはdomainフォルダに格納する

<.> 画面はroutesフォルダに格納する +
ファイル名はケバブケースとする

<.> 共通関数はutilsフォルダに格納する +
年齢計算とかaxiosのinterceptorなど

<.> ソース以外の資産(faviconや画像など)はpublicフォルダに格納する +
資産が多くなりそうな場合はサブディレクトリを検討する

== 認証処理

ログインが必要な画面ではAuthWrapperを組み込む

認証していないと使用できない画面.tsx
[source,js,indent=4]
----
import AuthWrapper from "../components/AuthWrapper";

export default function Hoge() {
  return (
    <>
      <AuthWrapper>
        <!-- ここにコードを記述 -->
      </AuthWrapper>
    </>
  );
}
----

上記のように、認証が必要な画面で認証チェックを行うコンポーネントを読み込む +
認証が不要な画面(ログイン画面など)はこのコンポーネントを読み込まなければいい

== フロントエンド開発におけるルール

=== 設計時に留意すること
* エラー処理
** エラーメッセージは利用者がこの後どうすればいいのかがわかるよう設計する
** APIのステータスコードによってエラー内容を切り分ける
* 入力フォーム
** 必須項目・任意項目がわかるように設計する
** プレースホルダーを工夫する
** テキストボックスに属性をつける
** コンポーネントを使用する場合、バリデーションはコンポーネント内で行う(コンポーネント内でzodを使用する)
** コンポーネントを使用しない場合、バリデーションはzodを使用する

=== 実装時に留意すること
* TypeScriptを使用する
** 警告を放置しないこと
* 日付の処理について
** date-fnsを使用する
* 各画面、コンポーネント内にCSSを直接記述しない
* URL組み立て時、文字列結合を使用せずURLオブジェクトを使用する
* 状態管理に格納するものは制限する(なんでもかんでも入れない)
* 画面表示時とAPI使用時は処理が完了するまでLoadingOverlayを表示する

== フロントエンドでの認証について

2024/12/11の打ち合わせにて決定

* axiosでAPIを呼ぶときリフレッシュのcookieの付与ルールについて
** cookieのpath属性
*** /api/v1/auth/refresh
*** ↑ axiosでのアクセス時に自動で付くことを確認する（タスク）
* 認証情報の保存先について（確認）
** JWT:localstorage、リフレッシュトークン:Cookie
*** 鍵がfront側にあるので厳密な保護は出来ないが鍵の暗号化しますか？（AITEL実績）
* JWTの検証について（認識合わせ・相談）
** expireの時間のみ検証
** 端末とサーバーの時刻が合わない可能性があるので、
*** 端末とサーバーの時間のズレを持っておくとかして考慮したい
**** offsetを持っておいて、端末の時間＋offsetでサーバー時間として扱う
*** AITEL同様送信→401確認→リフレッシュでも良いかも…（問題があれば）
* JWT・リフレッシュトークンの取得・更新・破棄について（認識合わせ）
** 認証→localstorageに保存
** ページ遷移→localstorageのJWTの有効期限チェック
** APIアクセス→localstorageのJWTの有効期限チェック
** 有効期限チェックに失敗→リフレッシュ（できればロックしておきたい）
** リフレッシュ→（401：JWT/RefreshTokenがおかしいorリフレッシュトークン期限切れ）→破棄・ログアウト
* JWT/RefreshTokenの渡し方
** jwt→httpヘッダのAuthorizationにBearer {jwt}
*** ログイン系のみ、ログインしていない状態でアクセスを許可する想定
** refreshtoken→httpヘッダのcookieのrefreshToken（必要ならハンドリングをする）
* 一旦、frontendから参照する予定があるclaim（認識合わせ）
** exp
** iat
* ログアウト時のrefreshTokenの破棄について
** frontendから制御はしない
* login系のAPIは完成したら連絡する

== APIClient生成方法

1. 最新のAPI仕様書(swagger.json)をDLし、Frontend/ResultCollector/OpenAPIフォルダに格納する
2. VSCodeでResultCollectorのルートフォルダを開く
3. app/utils/axiosInstance.tsの拡張子を##.tsx##に変更する
4. コンソールで##npx orval##を実行する
5. 3で変更したファイル名を元に戻す
6. app/api/フォルダに出力されたファイルのうち、##wellship.schemas.ts##をapp/domain/フォルダに移動する
7. app/api/フォルダの`wellship.ts`と`wellship.msw.ts`の##wellship.schemas##のimportするパスを"./wellship.schemas"から"../domain/wellship/schemas"に変更する

= 共通基盤機能

アプリケーション基盤としての共通機能について記載する。

== 認証

ユーザーを特定しシステムの正当な利用者であることを確認する。

共通機能候補は以下

- ログイン画面
- 認証
- 認証状態をチェックする（WebAPI）
- ログアウト

== 認可

ユーザーに対してシステムのリソースに対するアクセス権限を与える。

ロールベースアクセス制御（RBAC）
各ユーザーにロールを割り当ててアクセス制御する。

制御対象となるリソースの例

- 機能
- 画面
- データ

実装方法としては以下など。

- URLベースの判定
- エンドポイント単位
- 認可API

- https://www.macnica.co.jp/business/security/manufacturers/okta/tech_auth0_okta_rbac.html
- https://kenfdev.hateblo.jp/entry/2020/01/13/115032
- https://zenn.dev/dove/articles/8bed47a7a839ad

== エラーハンドリング

システムで発生したエラー事象を適切に制御してユーザーおよびシステム管理者に通知する。

エラーのレベルの例は以下。

- 通常
- 重大
- 深刻
- 致命的

== ロギング

ユーザーの操作やシステムの処理状況などをログとして記録する。

=== ログの種類

[cols="24,26,~"]
|===
|ログ名称 |目的・用途 |概要

|アクセスログ
|監査、障害調査
|ユーザーのシステムへのアクセス履歴を記録する。

|認証ログ
|監査
|ユーザー認証の成功、失敗を記録する。

|操作ログ
|監査、障害調査
|ユーザーがシステムの機能を利用した操作を記録する。

|エラーログ
|監視、障害調査
|システムで発生したエラーと詳細情報を記録する。

|デバッグログ
|開発時のデバッグ
|デバッグに利用するために変数の値や処理の進捗状況などを記録する。

|パフォーマンスログ
|性能分析
|バッチ処理時間やSQLのクエリ応答時間などを記録する。
|===

=== ログレベルの考え方

[cols="12,~,12"]
|===
|レベル |概要 |本番記録
|Trace
|最も詳細なレベル。開発のために使用される。
|-
|Debug
|デバッグ用。場合によっては本番でも記録する。
|-
|Info
|進捗状況やアプリケーションのライフイベントを記録する。
|〇
|Warn
|検証の問題や一時的なエラーに関する警告。
|〇
|Error
|機能が失敗したエラーや例外がキャッチされたエラー。
|〇
|Fatal
|最も重要なレベル。アプリケーションが中断される可能性あり。
|〇
|===
